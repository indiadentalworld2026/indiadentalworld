STANDARD 02

The 4-Way Test

Ask these four questions before building anything. A "No" to any one means redesign — not ship and fix later.

Before building anything, answer YES to all four:
1
Can a patient in Tier 2 India find this on Google without us running paid ads?
2
Will a first-time visitor trust this enough to book or register within 60 seconds?
3
Does this page load in under 2.5 seconds on a ₹8,000 Android on 4G?
4
Can this handle 10 lakh users without a rewrite?
STANDARD 03

Revenue & UX Framework

Every revenue stream must benefit the user, the platform, and the advertiser simultaneously. Any model that degrades UX is rejected.

"Every revenue stream must simultaneously benefit the user (better experience), the platform (sustainable income), and the clinic/brand (real ROI). Revenue that degrades user experience is rejected — it kills trust, kills SEO, and kills the platform."
Layer 1 — Foundation
Transaction
Booking commission 5–10%. Aligns platform success with clinic success. Build this first.
Layer 2 — Recurring
Subscription
Clinic premium ₹999–2,999/mo. Predictable MRR. Makes IDW fundable.
Layer 3 — Scale
Advertising
Sponsored listings, brand partnerships. High margin. Valuable only after traffic proof.
RuleStandardWhy
Sponsored contentAlways labelled "Sponsored" or "Ad"ASCI + Google policy. Violation = manual penalty
ReviewsNever incentivisedGoogle delists platforms that pay for reviews
Interstitial adsBannedGoogle Core Web Vitals penalty + user rage
Booking flowZero ads in booking pathSacred conversion path. Never break it
Mobile ad densityMax 30% screen at any timeGoogle "intrusive interstitials" threshold
Sponsored resultsMax 2 per search pageOrganic trust preserved
Ad load timeNo ad network adding >200msCore Web Vitals protected

STANDARD 05

Founder Workflow Standard

Minimal investment · Minimal developer load · Maximum growth · Maximum revenue · Faster building · Global applicability.

PrincipleWhat this means in practice
Prototype firstClaude builds the HTML prototype → founder reviews → developer gets exact spec. Zero guesswork on developer's end.
Database-drivenEvery page pulls from DB. No hardcoded content. Onboarding wizard fills the database — not manual entry.
Component-based UIBuild once, reuse everywhere. Clinic card on homepage = clinic card on search = clinic card on maps.
API-firstEvery feature exposed as an API. Web, mobile, and third-party integrations all use the same endpoints.
Token efficiencyPaste IDW Session Starter only at the start of a new Claude session. Never mid-session. Use memory for auto-load.
Build orderClinic registration → Clinic profile page → Search results → Homepage → Patient dashboard → PMS. In this order.
Revenue firstBooking commission wired before any advertising feature. Layer 1 before Layer 2 before Layer 3.
Verify before scale50 real verified clinics before any marketing spend. 500 before Series A pitch. Product-market fit before growth.

0–10k clinics. Algolia. No AI. ₹0–1,700/mo.
Typo tolerance · geo search · instant results · filters
Search: Stage 2
10k+ clinics. Elasticsearch + synonym rules. ~₹3–8k/mo.
Symptom mapping · synonym dict · ranked results
